## 1. 模块结构与移植边界

### 1.1 一次操作经过哪几层

```text
main.c                         应用层：你决定做什么
   │  读 ID、擦除、写入、读取、比较、显示
   ▼
W25Q64.c / W25Q64.h             芯片层：把操作组织成指令、地址、数据
   │  调用 Start / SwapByte / Stop
   ▼
MySPI.c / MySPI.h               接口层：控制 CS、交换一个字节
   │  调用 HAL_GPIO_WritePin / HAL_SPI_TransmitReceive
   ▼
SPI1 硬件                      自动产生 SCK、发送 MOSI、接收 MISO
   │
   ▼
W25Q64                         识别命令，执行读取、编程或擦除
```

**数据流示例：从 Flash 读取四字节。**

1. 主程序告诉 `W25Q64_ReadData()`：从哪里读、放到哪里、读多少。
2. W25Q64 层发送读取指令和地址，再接收四个字节。
3. MySPI 层控制片选，并用 HAL 完成每次字节交换。
4. 结果存入主程序提供的数组，主程序再负责显示或比较。

### 1.2 文件职责

| 文件 | 职责 | 当前学习要求 |
| --- | --- | --- |
| `Core/Src/main.c` | 安排实验顺序、准备数组、显示结果 | **由你编写** |
| `Core/Src/spi.c`、`Core/Inc/spi.h` | CubeMX 生成的 SPI1 初始化，以及 `hspi1` 的定义和声明 | 知道初始化和句柄的用途 |
| `User/Src/MySPI.c`、`User/Inc/MySPI.h` | 给江协驱动提供原来的 SPI 接口 | 重点看懂字节交换 |
| `User/Src/W25Q64.c`、`User/Inc/W25Q64.h` | 实现芯片指令及公开函数 | 重点学习 |
| `User/Inc/W25Q64_Ins.h` | 给指令码起名称 | 会查阅，不必背数值 |

### 1.3 标准库移植成 HAL，具体改了什么

| 位置 | 江协标准库版本 | 当前 HAL 版本 |
| --- | --- | --- |
| 片选电平 | `GPIO_WriteBit()` | `HAL_GPIO_WritePin()` |
| 硬件初始化 | `MySPI_Init()` 配置时钟、GPIO、SPI | 主程序已有的 `MX_GPIO_Init()`、`MX_SPI1_Init()` 完成 |
| `MySPI_Init()` | 初始化硬件并设置片选 | 保留函数入口，只将 CS 置高 |
| 单字节交换 | 等待 TXE、发送、等待 RXNE、读取 | `HAL_SPI_TransmitReceive()` |
| W25Q64 指令流程 | 江协原版 | **保持原样** |
| W25Q64 函数参数、返回类型 | 江协原版 | **保持原样，返回 `void`** |

`MySPI` 是为了保持接口和分层清楚。它仍然使用硬件 SPI，只有 CS 通过普通 GPIO 控制。

## 2. 四个必须理解的基础

### 2.1 CS 决定一条命令的边界

```text
CS 拉低 → 指令 → 地址（如果需要）→ 数据（如果需要）→ CS 拉高
```

- `MySPI_Start()`：拉低 CS，选中芯片，不发送任何字节。
- `MySPI_Stop()`：拉高 CS，结束命令，不发送任何字节。
- 一条命令的多个字节之间，CS 要保持低电平。
- 编程、擦除命令在 CS 拉高后开始执行内部操作。

**注意**：不要每交换一个字节就拉高 CS。芯片需要在同一个片选区间内接收完整命令。

### 2.2 SPI 读取也需要发送

SPI 每交换一个字节，STM32 都会同时发送和接收一个字节。

```text
发送有效指令：MOSI 有意义，当前收到的字节可能不需要
读取有效数据：发送占位字节产生时钟，保存 MISO 收到的数据
```

对应代码：

```c
/* 教学片段：驱动内部的两种用法 */
MySPI_SwapByte(0x9F);          // 发送指令，丢弃返回值
data = MySPI_SwapByte(0xFF);   // 发送占位数据，保存返回值
```

`W25Q64_DUMMY_BYTE` 的值为 `0xFF`，这里用于产生接收时钟。它不代表每条读取指令都需要额外插入一个空字节；是否需要额外等待周期，要看具体指令协议。

### 2.3 Flash 地址和 STM32 数组是两件事

```c
/* 教学片段：主程序中的单次调用示意 */
uint8_t read_data[4];
W25Q64_ReadData(0x000100, read_data, 4);
```

```text
W25Q64 存储位置                    STM32 内存位置

0x000100 的数据 ─────────────────→ read_data[0]
0x000101 的数据 ─────────────────→ read_data[1]
0x000102 的数据 ─────────────────→ read_data[2]
0x000103 的数据 ─────────────────→ read_data[3]
```

| 名称 | 表示什么 |
| --- | --- |
| `Address` | W25Q64 中的存储偏移地址 |
| `DataArray` | STM32 内存中数组的起始地址 |
| `Count` | 本次处理的字节数 |

**把数组传给函数，不会把数组内容变成 Flash 地址。** 函数通过数组指针取出待写数据，或把读回数据写进数组。

### 2.4 Flash 的容量、页和扇区

| 项目 | 数值 | 对程序的影响 |
| --- | --- | --- |
| 总容量 | 64 Mbit = 8 MiB = `0x800000` 字节 | 有效地址为 `0x000000～0x7FFFFF` |
| 一页 | 256 字节 = `0x100` 字节 | 一次页编程不能跨页 |
| 一个扇区 | 4096 字节 = `0x1000` 字节 | 扇区擦除影响整个 4 KiB |

Flash 的位变化规则：

```text
擦除：把位恢复为 1，擦除后的字节为 FF
编程：可以把位从 1 改成 0
```

例如：`FF → 11` 可以编程；`00 → 11` 需要先擦除。

**实验中的基本顺序：擦除目标扇区 → 写入数据 → 读回验证。**

## 3. MySPI：底层怎样接上 HAL

### 3.1 四个简单函数：认识职责即可

位置：[MySPI.c](User/Src/MySPI.c)，第 10、23、33、43 行。

| 函数 | 输入参数 | 返回值 | 内部动作与调用时机 |
| --- | --- | --- | --- |
| `MySPI_W_SS(BitValue)` | `0` 或 `1` | 无 | 调用 HAL 设置 CS；由其他 MySPI 函数使用 |
| `MySPI_Init()` | 无 | 无 | CS 置高；由 `W25Q64_Init()` 调用 |
| `MySPI_Start()` | 无 | 无 | CS 拉低；一条命令开始时调用 |
| `MySPI_Stop()` | 无 | 无 | CS 拉高；一条命令结束时调用 |

片选函数中的名称：

| 名称或类型 | 含义与用途 | 约束 |
| --- | --- | --- |
| `FLASH_CS_GPIO_Port` | 片选端口宏，当前为 `GPIOA` | 换接线时必须与实际端口对应 |
| `FLASH_CS_Pin` | 片选引脚宏，当前为 `GPIO_PIN_4` | 当前绑定 PA4 |
| `GPIO_PinState` | HAL 的 GPIO 电平类型 | `GPIO_PIN_RESET` 为低，`GPIO_PIN_SET` 为高 |

`(GPIO_PinState)BitValue` 把传入的 `0/1` 转换成 HAL 电平类型，因此按接口约定只传 `0` 或 `1`。这些函数没有错误状态返回，调用前需完成 GPIO 初始化。

### 3.2 MySPI_SwapByte：必须读懂的核心

位置：[MySPI.c](User/Src/MySPI.c)，第 55 行。

```c
uint8_t MySPI_SwapByte(uint8_t ByteSend)
{
    uint8_t ByteReceive = 0;

    HAL_SPI_TransmitReceive(&hspi1, &ByteSend, &ByteReceive,
                            1, HAL_MAX_DELAY);

    return ByteReceive;
}
```

**函数职责**：在当前片选状态下交换一个字节，不改变 CS。

| 项目 | 说明 |
| --- | --- |
| 输入 `ByteSend` | 要发送的 8 位数据 |
| 输出 | 通过函数返回值返回同时收到的 8 位数据 |
| 调用时机 | SPI 初始化完成，且芯片已被选中之后 |
| 内部流程 | 准备接收变量 → HAL 阻塞收发 → 返回接收值 |
| 错误处理 | 当前保留原版接口，没有向上层报告 HAL 错误 |

HAL 参数逐项对应：

| 参数 | 含义 |
| --- | --- |
| `&hspi1` | 使用 SPI1 的 HAL 句柄 |
| `&ByteSend` | 发送数据所在的内存地址 |
| `&ByteReceive` | 接收数据应写入的内存地址 |
| `1` | 交换一个数据单元；当前为 8 位，即一个字节 |
| `HAL_MAX_DELAY` | 本次阻塞调用不设置有限超时 |

`hspi1` 的类型是 `SPI_HandleTypeDef`，由生成的 `spi.c` 定义、`spi.h` 声明。它包含外设实例、配置和运行状态等信息。当前知道“用它指定 SPI1”即可，不需要重复定义或手动修改其内部字段。

> **两种返回值不要混淆**：`HAL_SPI_TransmitReceive()` 返回 HAL 通信状态；`MySPI_SwapByte()` 返回接收到的数据。当前代码没有使用前者。

`HAL_MAX_DELAY` 这类 HAL 宏和 HAL 内部寄存器处理会用即可。不要将这里改成异步 DMA 调用后仍立即返回 `ByteReceive`；上层依赖“字节交换完成后才继续”的同步行为。

## 4. W25Q64：按实验顺序理解函数

### 4.1 对外接口总览

位置：[W25Q64.h](User/Inc/W25Q64.h)，第 6～10 行。

| 顺序 | 接口 | 一句话理解 |
| :---: | --- | --- |
| 1 | `W25Q64_Init()` | 建立模块初始状态 |
| 2 | `W25Q64_ReadID(MID, DID)` | 读取芯片身份信息 |
| 3 | `W25Q64_SectorErase(Address)` | 擦除地址所在的扇区 |
| 4 | `W25Q64_PageProgram(Address, DataArray, Count)` | 把数组写入 Flash 的一页范围内 |
| 5 | `W25Q64_ReadData(Address, DataArray, Count)` | 把 Flash 数据读进数组 |

**五个接口都返回 `void`，不能写成 `status = W25Q64_ReadID(...)`。** 指针输出数据不等于函数有返回值。

### 4.2 W25Q64_Init：初始化调用关系

位置：[W25Q64.c](User/Src/W25Q64.c)，第 10 行。

```text
MX_GPIO_Init()、MX_SPI1_Init() 已执行
    ↓
W25Q64_Init()
    ↓
MySPI_Init()
    ↓
CS 置高
```

- **参数、返回值**：均无。
- **调用时机**：主程序的外设初始化完成后。
- **职责边界**：不重复初始化 SPI，不读 ID，不检测芯片是否存在。
- **注意**：函数执行结束，只说明执行了初始化动作，不能据此断定接线和通信正常。

### 4.3 W25Q64_ReadID：建议逐行读懂

位置：[W25Q64.c](User/Src/W25Q64.c)，第 21 行。

```c
void W25Q64_ReadID(uint8_t *MID, uint16_t *DID);
```

| 参数 | 方向 | 含义 |
| --- | --- | --- |
| `MID` | 输出 | 指向一个 8 位变量，接收厂商 ID |
| `DID` | 输出 | 指向一个 16 位变量，接收后两个 JEDEC ID 字节 |

调用示意（放置于主程序初始化之后，非完整主程序）：

```c
uint8_t mid;
uint16_t did;

W25Q64_ReadID(&mid, &did);
```

指针和类型只需先掌握这些：

| 写法 | 含义 |
| --- | --- |
| `uint8_t`、`uint16_t`、`uint32_t` | 分别为 8、16、32 位无符号整数，来自 `<stdint.h>` |
| `&mid` | 取得主程序变量的地址 |
| `uint8_t *MID` | 用一个指针接收这个地址 |
| `*MID = ...` | 把结果写入该地址对应的变量 |

完整交换顺序：

```text
CS↓
STM32 发送：  9F       FF       FF       FF
芯片返回：   丢弃      EF       40       17    （常见型号示例）
CS↑
```

| 代码动作 | 变量变化 |
| --- | --- |
| 发送 `W25Q64_JEDEC_ID` | 告诉芯片接下来输出 ID，当前接收值丢弃 |
| 第一遍交换读取 | `*MID = 0xEF` |
| 第二遍交换读取 | `*DID = 0x0040` |
| `*DID <<= 8` | `*DID = 0x4000` |
| 第三遍读取并按位或 | `*DID = 0x4017` |

**常见 W25Q64 型号**：MID 为 `0xEF`，DID 为 `0x4017`，具体以芯片型号手册为准。这里使用的是 `0x9F` JEDEC ID 指令，不能直接拿其他读 ID 指令的返回格式套用。

**错误与约束**：两个指针必须有效；当前函数没有空指针检查，也没有通信状态返回。主程序用读取结果判断通信是否合理。

### 4.4 W25Q64_SectorErase：先明确擦除范围

位置：[W25Q64.c](User/Src/W25Q64.c)，第 100 行。

```c
void W25Q64_SectorErase(uint32_t Address);
```

- **输入**：芯片范围内的一个地址，指定擦除该地址所在扇区。
- **返回值**：无。
- **调用时机**：需要将目标区域恢复为 `0xFF` 时，实验中通常放在写入之前。
- **内部流程**：写使能 → 发送 `0x20` 和三字节地址 → 拉高 CS → 等待忙。
- **错误与约束**：不检查地址范围，不报告擦除结果，整个扇区的数据都会被清除。

```text
扇区 0：000000～000FFF
扇区 1：001000～001FFF
扇区 2：002000～002FFF
```

`SectorErase(0x000000)` 和 `SectorErase(0x000123)` 指向同一个扇区，都会清除 `0x000000～0x000FFF`。

建议在主程序传扇区起始地址，便于明确操作范围。**不要为了写四字节，就忽略扇区中另外 4092 字节原有的数据。**

### 4.5 W25Q64_PageProgram：掌握参数与页边界

位置：[W25Q64.c](User/Src/W25Q64.c)，第 75 行。

```c
void W25Q64_PageProgram(
    uint32_t Address, uint8_t *DataArray, uint16_t Count);
```

| 参数 | 含义与约束 |
| --- | --- |
| `Address` | Flash 写入起始地址，必须在芯片范围内 |
| `DataArray` | 指向待写数组；函数从中读取数据 |
| `Count` | 写入字节数，正常使用取 1～256，且不能跨页 |

- **返回值**：无。
- **调用时机**：目标区域满足编程条件之后；初次实验先擦除再写。
- **内部流程**：写使能 → 发送 `0x02` → 发送三字节地址 → 发送数组数据 → 拉高 CS → 等待忙。
- **职责边界**：不自动擦除、不自动拆分跨页数据、不检查参数、不报告成功或失败。

发送地址的三行：

```c
MySPI_SwapByte(Address >> 16);
MySPI_SwapByte(Address >> 8);
MySPI_SwapByte(Address);
```

以 `Address = 0x123456` 为例，依次发送 `0x12`、`0x34`、`0x56`。因为交换函数参数是 `uint8_t`，传入时只保留低八位。读取和擦除函数也使用相同的地址发送方式。

**页边界是写入规则中最容易用错的地方。**

```text
页 0：000000～0000FF
页 1：000100～0001FF
```

| 起始地址 | 当前页剩余空间 | 一次最多写入 |
| --- | --- | ---: |
| `0x000000` | 一整页 | 256 字节 |
| `0x000080` | 后半页 | 128 字节 |
| `0x0000FE` | 最后两个地址 | 2 字节 |

调用者需要保证：

```text
Count ≤ 256 − (Address % 256)
```

超过边界不会按预期自动写下一页，可能在当前页内回绕。注释中的 `Count: 0～256` 只是原版说明；正常数据写入使用非零长度。

调用示意（由主程序在擦除后执行）：

```c
uint8_t write_data[] = {0x11, 0x22, 0x33, 0x44};
W25Q64_PageProgram(0x000000, write_data, sizeof(write_data));
```

这里 `sizeof(write_data)` 在数组定义所在作用域内得到数组总字节数，即 4。不要在函数中对已经退化成指针的 `DataArray` 使用 `sizeof` 来推断原数组长度。

### 4.6 W25Q64_ReadData：把结果读进接收数组

位置：[W25Q64.c](User/Src/W25Q64.c)，第 121 行。

```c
void W25Q64_ReadData(
    uint32_t Address, uint8_t *DataArray, uint32_t Count);
```

| 参数 | 含义与约束 |
| --- | --- |
| `Address` | Flash 读取起始地址 |
| `DataArray` | 指向接收数组；函数会修改数组内容 |
| `Count` | 读取字节数；不能超过接收数组空间和 Flash 剩余容量 |

- **返回值**：无，通过数组输出数据。
- **调用时机**：芯片空闲时；本实验在前一次同步擦除、编程之后调用。
- **内部流程**：发送 `0x03` → 三字节地址 → 循环交换接收 → 结束命令。
- **错误与约束**：没有数组大小检查、地址越界检查和错误状态返回；本函数自身也没有调用忙等待。

循环中的关键动作：

```c
DataArray[i] = MySPI_SwapByte(W25Q64_DUMMY_BYTE);
```

每次发送一个占位字节，接收一个有效数据，依次存入数组。芯片内部的读取地址会自动递增，不需要每读一个字节就重新发送地址。

**普通读取可以跨页；单次页编程不能跨页。** 读取前不需要写使能，也不需要擦除。

## 5. 写使能与忙等待：两个内部辅助步骤

这两个函数在 `W25Q64.c` 中定义，当前没有声明在公开头文件里。主程序通常不用直接调用，因为擦除和页编程已经包含它们。

### 5.1 W25Q64_WriteEnable

位置：[W25Q64.c](User/Src/W25Q64.c)，第 37 行。

| 项目 | 内容 |
| --- | --- |
| 职责 | 发送写使能指令，允许后续编程或擦除 |
| 参数、返回值 | 均无 |
| 调用时机 | 每次页编程、扇区擦除之前，由驱动自动调用 |
| 内部流程 | `CS↓ → 06 → CS↑` |
| 错误处理 | 原版没有检查写使能位 WEL 是否成功置位 |

必须保留两条独立命令的边界：

```text
CS↓ → 06 → CS↑                         写使能
CS↓ → 02 → 地址 → 数据 → CS↑            页编程
```

不能让 CS 一直为低，然后把 `06` 与 `02` 当成同一条命令发送。

### 5.2 W25Q64_WaitBusy

位置：[W25Q64.c](User/Src/W25Q64.c)，第 49 行。

| 项目 | 内容 |
| --- | --- |
| 职责 | 查询状态寄存器 1，等待内部编程、擦除结束 |
| 参数、返回值 | 均无 |
| 调用时机 | 页编程、擦除命令发出并结束后，由驱动自动调用 |
| 内部流程 | 发送 `0x05` → 连续读取状态 → 检查 bit0 → 空闲或计数耗尽后退出 |
| 错误处理 | 查询计数耗尽后 `break`，没有向上层报告超时 |

状态位含义：

| 位 | 名称 | 值为 0 | 值为 1 |
| --- | --- | --- | --- |
| bit0 | BUSY / WIP | 内部空闲 | 内部编程或擦除中 |
| bit1 | WEL | 未写使能 | 已写使能 |

当前忙等待只检查 bit0：

```c
(MySPI_SwapByte(W25Q64_DUMMY_BYTE) & 0x01) == 0x01
```

`0x01` 是用于提取最低位的掩码，按位与后只剩 bit0。保持 CS 为低、连续读取状态是合法用法，不必每次重新发送 `0x05`。

**必须区分两个“完成”：**

```text
SPI 传输完成：指令、地址、数据已经发给芯片
Flash 操作完成：芯片内部真正完成存储单元的编程或擦除
```

`Timeout = 100000` 表示剩余查询次数，实际耗时取决于 SPI 速度和函数开销，并不是毫秒数。另外，底层 HAL 收发使用无限等待，外层查询计数不能覆盖底层一直阻塞的情况。

这份代码保留教学实现：正常情况下等到操作结束再返回，但**函数返回不等于已经确认写入成功**。最终仍用读回数据验证。

### 5.3 只需认识当前使用的七个宏

位置：[W25Q64_Ins.h](User/Inc/W25Q64_Ins.h)。

| 宏 | 值 | 用途 |
| --- | --- | --- |
| `W25Q64_JEDEC_ID` | `0x9F` | 读取三个 JEDEC ID 字节 |
| `W25Q64_WRITE_ENABLE` | `0x06` | 写使能 |
| `W25Q64_READ_STATUS_REGISTER_1` | `0x05` | 读取状态寄存器 1 |
| `W25Q64_PAGE_PROGRAM` | `0x02` | 页编程 |
| `W25Q64_SECTOR_ERASE_4KB` | `0x20` | 4 KiB 扇区擦除 |
| `W25Q64_READ_DATA` | `0x03` | 普通读取 |
| `W25Q64_DUMMY_BYTE` | `0xFF` | 读取阶段发送的占位数据，不是此处使用的指令 |

宏只是给数值起名字，提高可读性。命令格式由芯片手册决定，不因使用 HAL 而改变。其他未使用的指令宏先保留即可，暂时不需要学习。

## 6. 怎样独立编写主程序

### 6.1 第一阶段：只验证 ID

**目标：确认底层通信正常，不进行擦写。**

1. 在 `main.c` 的用户头文件区包含 `W25Q64.h`。
2. 准备一个 `uint8_t` 变量保存 MID、一个 `uint16_t` 变量保存 DID。
3. 保留生成的 GPIO、SPI 初始化。
4. 在初始化后的用户区调用 `W25Q64_Init()`。
5. 调用 `W25Q64_ReadID()`，传入两个变量的地址。
6. 用调试器或 OLED 观察结果；显示由你已有的 OLED 接口完成。

**验收点**：结果稳定，并与实际芯片型号相符。ID 异常时先排查通信，不继续叠加写入逻辑。

### 6.2 第二阶段：完成一次读写验证

**目标：把 STM32 数组存入 Flash，再读取出来比较。**

```text
准备写数组和读数组
    ↓
选择一个专门用于实验的扇区
    ↓
擦除该扇区
    ↓
可选：先读回几个字节，检查是否为 FF
    ↓
页编程写入数组
    ↓
从相同起始地址读回，长度与写入一致
    ↓
逐字节比较，显示写入值、读取值和比较结果
```

编写时自行决定变量名和显示位置，但检查以下条件：

| 检查项 | 为什么 |
| --- | --- |
| 写数组、读数组分别存放 | 才能比较期望值与实际值 |
| 读写起始地址相同 | 否则比较的不是同一段存储区域 |
| 字节数一致、缓冲区足够 | 避免漏读、漏写或越界 |
| 页编程范围不跨页 | 原驱动不会自动拆分 |
| 擦除范围允许被清空 | 扇区内所有原数据都会丢失 |
| 擦除、写入放在单次流程 | 避免主循环持续重复擦写 |

**验收点**：每个读回字节都与写数组对应字节一致。只看函数执行完、没有卡住，不能证明写入成功。

### 6.3 第三阶段：验证掉电保存

初次读写成功后，可以再做：

1. 写入并确认数据正确。
2. 下一次实验只执行初始化、读取和显示，不再先擦除或重新写入。
3. 重新上电，读取同一地址，检查数据是否保留。

如果每次上电都先擦除、再写入相同数据，就无法单独验证掉电保存。

## 7. 常见问题与排查

| 现象 | 优先检查 |
| --- | --- |
| ID 一直为 `FF FF FF` | CS 是否真正拉低，MISO、供电、接线及芯片型号是否正确；这不是单一故障的确定结论 |
| ID 一直为 `00 00 00` | 接收路径、片选、供电和 SPI 传输是否正常；当前接口不会报告 HAL 错误 |
| ID 正常，写入后仍为 `FF` | 写使能、写保护状态、地址和命令时序；读 ID 正常不代表编程一定成功 |
| 部分数据错位或页开头被改动 | 页编程是否跨页，`Count` 是否超过当前页剩余空间 |
| 第二次改写数据不符合预期 | 是否试图直接把位从 0 改为 1，是否需要先擦除 |
| 相邻数据一起消失 | 是否擦除了它们所在的同一个 4 KiB 扇区 |
| 程序卡住 | 用调试器确认停在 HAL 传输还是忙查询；两者等待的对象不同 |
| 显示结果不更新 | 先用调试器看变量，再检查 OLED 的显示与刷新调用 |

当前版本是同步、阻塞式教学驱动，适合主循环单一调用。不要在中断中执行长时间等待，也不要让多个执行流程同时操作 SPI1 或同一芯片。
